## 6. 服务器 AI 改造方向 (PADP_v3 风格)

### 6.1 目标: 参考 `PADP_v3/diffusion_policy/serving/` 实现 server-client 拆分

PADP_v3 用了 `AsyncVectorEnv` (server 端 multiprocessing spawn N worker) + 1 WebSocket + batched 帧。VLA 当前是 `RobomimicEnv` (single) + TCP + 单帧。

### 6.2 拆分目标 (用户原话)

> "最终完成所有内容" — 让 server / client 都按 PADP_v3 风格拆分:
> - **server 端**: 跑 25 envs via `gym.vector.AsyncVectorEnv`, accept WebSocket (或 TCP), 处理 `step`/`reset` batched
> - **client 端**: 暴露 1 个 TCP + batched 帧, send_recv `{"op": "step", "action": (B, n_action_steps, D_a)}`
> - **policy 端**: 单独 process, 暴露 WebSocket/TCP, 接收 batched obs → batched inference → 回 batched action

### 6.3 现有 VLA 跟 PADP_v3 差异

| 维度 | PADP_v3 | VLA 当前 (v1.3.1) |
|---|---|---|
| transport | WebSocket | raw TCP (msgpack + 4B 长度前缀) |
| batched 帧 | ✅ 完整 (`op: "step" / "reset"` + batched obs/action) | ✅ 协议层支持 (BATCHED_OBS/BATCHED_ACTION), client 25 parallel 没跑通 (1 GPU 撞 EGL) |
| N envs 位置 | server 端 (`AsyncVectorEnv` + 25 worker process) | client 端 (`AsyncVectorEnv`, 5+ env 撞 EGL) |
| policy 端 | 独立 process (WebSocket 暴露给 runner) | 跟 server 同 process (`padp_for_test_server.py:load_policy_from_ckpt` 加载 + `predict_action` inline 调) |
| config 拆分 | `robomimic_padp_position_wise_v3_model_v6.yaml` (model) + `robomimic_padp_position_wise_v3_env_v6.yaml` (env) | 1 个 yaml (`padp_for_test_golden.yaml`), policy + data + train + rollout 都在里面 |

## 10. 限制 / 已知问题 (用户决策后修)

1. **1 GPU 跑不动 5+ robomimic env** (EGL 资源) — fallback 到 25 sequential episodes
2. **7D loss 跌不到 0.01** (axis_angle 比 rot6d 难学 10-30 倍) — 4 路 yaml 用统一 `loss_threshold=0.01`, 7D 永远进不了 phase2 → 没 score ckpt
3. **OSMesa 软渲染** 装不对 (OpenGL `_p.glGetError` 失败) — 没法 disable GPU 渲染
4. **本机 VLA-v1.1/E_cti/configs/ 目录不存在** — 同步 yaml 失败, 用户机器 cp 完要 `mkdir -p VLA-v1.1/E_cti/configs/` 再 cp
5. **PADP_v3 WebSocket vs VLA TCP** — server/client 协议不一致, 改造时统一选一种
