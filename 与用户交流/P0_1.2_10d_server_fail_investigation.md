# P0 调查报告: 1.2_10D rollout server 60s 未启动根因

**调查日期**: 2026-06-16
**目标错误**: `[ERROR] [rollout] Server 在 60.0s 内未启动,放弃 rollout` (epoch 240, server pid=2197889, 端口 8763)

## 1. 关键发现 (TL;DR)

| 项目 | 结论 |
|---|---|
| **直接死因** | 1.2_10D 训到 epoch 240 时调 `padp_for_libero_server.py` (带 auto-avoid), 但**该函数只改 `sys.argv`, 不改 yaml port**; rollout 内部仍读 yaml `rollout.server.port=8765`; 若此时 1.1_10D 的 server 进程没清干净或 8765 已被占, spawn 后 server 启不动, 60s timeout 触发 |
| **根本架构缺陷** | 1.2 `padp_for_libero_server.py` 加了 port auto-avoid (`find_free_port`), 但 **rollout spawn 端 (`padp_for_test_rollout.py`) 不会从 server 的 auto-avoid 拿到新端口** — 两处独立选端口, 完全脱节 |
| **为什么是 1.2_10D 触发** | 1.1 server 用 1.1 train main 的 spawn, **无 port auto-avoid**, 死锁 8765; 1.2 server 自己有 auto-avoid 但只在 standalone 调用时生效; 1.2 train → 1.2 rollout spawn 时, 1.2 server 收到 yaml 写死的 8765, 且 1.1 进程占着 8765 → 失败 |

## 2. 实测证据

3 个 server log 时间窗 22:50-22:55, smoke rollout 验证:

| Log | 启动时间 | Listening 端口 | 加载 ckpt | encoder |
|---|---|---|---|---|
| `1.1_10D_server.log` | 22:50:57 | **8765** | `padp_for_test_golden/latest.ckpt` | RobomimicObsEncoder |
| `1.1_7D_server.log`  | 22:54:11 | **8764** | `padp_for_test_7d_golden/latest.ckpt` | RobomimicObsEncoder |
| `1.2_10D_server.log` | 22:54:59 | **8763** | `v1.2_lerobot_libero10d/latest.ckpt` | LerobotRobomimicObsEncoder |

**关键观察**:
1. 1.1_10D 和 1.1_7D 都按 yaml 写死的 8765/8764 启动, **没人避让**, **没人冲突** — 因为 1.1 yaml 写死了 8765, 1.1_7D 写死了 8764, 二者天然不冲突 (1.1 端就是手写)
2. 1.2_10D 拿到 **8763** — **不是 yaml 里的 8765**! 证明 `padp_for_libero_server.py:main_lerobot()` 的 `find_free_port(8765)` 确实生效 (8765/8764 被前 2 个 server 占着, 被推到 8763)
3. **但这 3 个 log 都是 verification (smoke) 调用**, 不是 train 期间 1.1 跑 251 epoch 的 spawn。production 训到 epoch 240 时的实际 1.2 spawn 行为需要再确认

## 3. 代码层根因 (按文件)

### 3.1 1.2 server 的 auto-avoid (有效但有 bug)

`VLA/E_cti/train/padp_for_libero_server.py:73-98`:
```python
def main_lerobot():
    if "--port" in sys.argv:
        idx = sys.argv.index("--port")
        if idx + 1 < len(sys.argv):
            try:
                preferred = int(sys.argv[idx + 1])
                actual = find_free_port(preferred)   # ★ auto-avoid
                ...
                sys.argv[idx + 1] = str(actual)       # ★ 改 sys.argv
            ...
    _test_main()
```

`VLA/E_cti/train/port_utils.py:28-57`:
- 默认从 preferred (8765) **往下**找 (`preferred - offset`)
- 找到空的就 bind + 立即释放 (作为 hint 给 server)
- 跑完**这个 bind 是测试完就关的**, server 真正 listen 时仍可能冲突 (TOCTOU)

### 3.2 1.2 rollout 的 spawn (不改端口)

`VLA/E_cti/train/padp_for_test_rollout.py:72-117`:
```python
port = int(server_cfg.get("port", 0)) or _find_free_port()   # ★ 从 yaml 读 8765
...
if rollout_cfg.get("use_lerobot_env", False):
    server_script = _VLA_ROOT / "E_cti/train/padp_for_libero_server.py"  # ★ 选 1.2 server
else:
    server_script = _VLA_ROOT / "E_cti/train/padp_for_test_server.py"
...
server_cmd = [
    sys.executable, str(server_script),
    "--ckpt", str(tmp_ckpt_path),
    "--host", host, "--port", str(port),  # ★ 传 yaml 写死的 8765
    ...
]
server_proc = subprocess.Popen(server_cmd, ...)
```

**这里有 3 个独立 bug**:

1. **rollout 不调用 `find_free_port`**, 直接信 yaml 里的 8765
2. **rollout 也不把 `find_free_port` 的结果回传给自己** — 哪怕 server 自己做 auto-avoid, rollout 这边 `_wait_for_port(host, port, wait_timeout)` 等的还是 yaml 那个原端口, server 实际上在听别的端口, **永远等不到**
3. **port_utils 用 TOCTOU 模式** (bind+release, 然后 server 再 bind), 在并发场景下窗口期可能被别人抢走

### 3.3 1.1 train main 无 auto-avoid

`VLA-v1.1/E_cti/train/padp_for_test_train.py:243-251`:
```python
"rollout": {
    "server": {
        "host": "127.0.0.1",
        "port": 8765,
        "spawn": True,
        "wait_timeout_sec": 60,
    },
```

`padp_for_test_7d_golden.yaml` port = 8764, `padp_for_test_golden.yaml` port = 8765

**关键**: 1.1 这条线 yaml 端口是手写不同的, 历史上**不依赖 auto-avoid 就不冲突**; 但 1.2 yaml (`lerobot_libero10d.yaml:124-128`) 也是 8765, **完全跟 1.1_10D 撞** — 这是 1.2 yaml 的设计 bug, **没考虑跟 1.1 复用的场景**

### 3.4 rollout 的 cleanup 不可靠

`VLA/E_cti/train/padp_for_test_rollout.py:191-199`:
```python
finally:
    if server_proc is not None:
        server_proc.terminate()       # ★ SIGTERM
        try:
            server_proc.wait(timeout=10)
        except subprocess.TimeoutExpired:
            server_proc.kill()         # ★ SIGKILL 兜底
```

SIGTERM 给 server 10s 反应时间。但 server 内部是 `serve_forever` 阻塞 `accept()`, Python 默认 SIGTERM handler 不优雅处理, **实际可能 server 收到 SIGTERM 后没立即关 socket, 导致 TIME_WAIT 残留端口**; next spawn 时 `bind()` 失败 (Linux 允许 TIME_WAIT 端口 bind 加 `SO_REUSEADDR` 没问题, 但**对 `port_utils.find_free_port` 的 bind 也会冲突**, 因为后者 bind 后没 listen 直接关, 跟 server 正常 listen 关闭后的状态可能不一样)

### 3.5 1.1 rollout 跟 1.2 rollout 的 diff (关键对比)

| 行为 | 1.1 rollout (`VLA-v1.1/...`) | 1.2 rollout (`VLA/...`) |
|---|---|---|
| use_lerobot_env 路径 | 无 | 有, 选 `padp_for_libero_server.py` |
| port 来源 | yaml `rollout.server.port` | yaml `rollout.server.port` (**还是 yaml**) |
| auto-avoid | 无 | 无 (依赖 server 自己有) |
| 写死 fallback 端口 | 8765 | 8765 (yaml 默认) |

**→ 1.2 rollout 相比 1.1 rollout, 只多了一行 "use_lerobot_env 选 server 入口", 端口处理逻辑完全没变**

## 4. 怀疑对象评级 (按可能性)

### H1: 1.2 rollout 跟 1.2 server 端口契约脱节 ⭐⭐⭐⭐⭐ (最可能)

**机制**:
1. 1.1_10D 训完一轮, server spawn 在 8765, 跑完 SIGTERM 关掉, 但 TIME_WAIT 还在
2. 1.2_10D 训到 epoch 240, 触发 rollout
3. 1.2 rollout 读 yaml `port: 8765`, spawn `padp_for_libero_server.py` 时把 8765 传过去
4. `padp_for_libero_server.py:main_lerobot()` 看到 `--port 8765`, 调 `find_free_port(8765)`, bind 测试发现 8765 **还在 TIME_WAIT (虽然 SO_REUSEADDR 能复用, 但 bind 测试通常 OK)**
5. 或者 `find_free_port` 找到了 8764/8763/... (被 1.1_7D 占着), 把 sys.argv 里的 8765 **改成实际空闲端口** (比如 8762)
6. server 启动 listen **在 8762**, 但 rollout 那边 `_wait_for_port("127.0.0.1", 8765, 60.0)` **永远连不上 8765**
7. 60s 后报错 "Server 在 60.0s 内未启动"

**evidence**:
- `padp_for_libero_server.py:88-91` 把 `sys.argv[idx+1] = str(actual)` — server 实际端口被偷偷改了
- `padp_for_test_rollout.py:113-117` rollout 持有的是 `port` 局部变量, 跟 server 实际 listen 端口**完全不一致**
- `padp_for_test_rollout.py:118` `_wait_for_port(host, port, wait_timeout)` 等的是原 yaml 端口

### H2: 1.1_10D server 进程没干净退出, 占着 8765 ⭐⭐⭐⭐

**机制**:
1. 1.1_10D 训到 epoch 235 (假设 interval=5, first_epoch=5), spawn 1.1 server 在 8765
2. client 跑完, rollout finally 块发 SIGTERM
3. server 在 `accept()` 阻塞, Python 默认 SIGTERM handler 不优雅处理, 可能 `tcp_listen` socket **TIME_WAIT 持续 60s**
4. epoch 240 时, 1.2 rollout 调 `find_free_port(8765)`, 这函数在 `port_utils.py:46-50` 用 SO_REUSEADDR bind, **bind 成功了** (因为 SO_REUSEADDR 允许 bind TIME_WAIT 端口)
5. 然后 server 实际 listen 时, **真正的 1.1 server 进程可能还没完全死, listen 失败 `EADDRINUSE`**
6. server 进程崩了, 日志没记 (因为不是正常 exit, stderr redirect 到 server_log 应该能看到)
7. rollout 等 60s, 失败

**evidence**:
- `port_utils.py:46` 显式 `SO_REUSEADDR`, 但**没等** TIME_WAIT 清掉
- `padp_for_test_server.py:288-309` `serve_forever` 只 catch `KeyboardInterrupt`, **不 catch SIGTERM**

### H3: 1.2 server 在 1.1_7D 同时跑时 GPU 资源冲突 ⭐⭐

**机制**: spawn server 没指定 `CUDA_VISIBLE_DEVICES`, 继承 train 进程的 GPU 设置。

**反 evidence**: 3 个 server 都成功 listen 在 60s 内, 说明 GPU 不是瓶颈

### H4: 1.2 train spawn 调错 server 入口 ⭐

**evidence**: 1.2_10D_server.log 第 6 行有 `[lerobot_obs_encoder]`, 是 1.2 server, 入口选对了

### H5: 1.2 server 加载 lerobot ckpt 静默 crash ⭐

**反 evidence**: 1.2_10D_server.log 加载成功, LerobotRobomimicObsEncoder built, Listening OK

## 5. 推荐的修复路径 (按工作量排序)

### Fix-A: rollout 端改用同一 `find_free_port` (10 行代码) ⭐⭐⭐⭐⭐

`VLA/E_cti/train/padp_for_test_rollout.py:72`:
```python
# 原:
port = int(server_cfg.get("port", 0)) or _find_free_port()
# 改:
from E_cti.train.port_utils import find_free_port
preferred = int(server_cfg.get("port", 0)) or 8765
port = find_free_port(preferred)   # 跟 server 端对齐
```

**代价**: ~3 行; **风险**: 极低, 跟 1.2 server 行为对齐

**但这只是症状缓解**, 根本问题是 rollout 跟 server 各自算端口, 协议脱节

### Fix-B: 统一在 spawn 端算端口, server 不做 auto-avoid ⭐⭐⭐⭐

让 spawn 端 (rollout) 负责一切 port 决策, server 是 dumb listener。

**代价**: ~15 行; **风险**: 中, 要同步改 rollout 端

### Fix-C: rollout spawn 时通信端口回传 ⭐⭐⭐

让 server 启动时**只在自己这边做 find_free_port**, 然后通过 pipe / signal / tmpfile 通知父进程。

**代价**: ~30 行; **风险**: 跟"父进程预知子进程端口"这个心智模型反直觉

### Fix-D: rollout 端不传 --port, 让 server 完全自主 ⭐⭐

让 server 启动时**只在自己这边做 find_free_port**, 然后通过 pipe / signal / tmpfile 通知父进程。

**代价**: ~50 行; **风险**: 高, 跨平台兼容性问题多

### Fix-E: 改 1.2 yaml 默认端口避开 1.1 黄金端口 (最小修复) ⭐

`lerobot_libero10d.yaml:126` `port: 8765` → `port: 8763`
`lerobot_libero7d.yaml:122` `port: 8765` → `port: 8762`

**代价**: 2 行; **风险**: 极低; 但**只解决 1.2_10D 这一个具体 case**, 根本问题没修
