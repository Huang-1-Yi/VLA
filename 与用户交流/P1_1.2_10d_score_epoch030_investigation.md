## 4. 1.2_10D score ckpt 为何从 epoch 30 开始 (vs 1.1_10D 从 5 开始)

### 4.1 Phase 1 → Phase 2 切换的逻辑

从日志 (运行记录.md 第 488-700 行) 看, 7D 跑 (loss > 0.01) 一直不进入 Phase 2:
```
[2026-06-16 04:06:10] [padp_for_test_train] [INFO] [Rollout] epoch=250 跳过(Phase 1: loss=0.0172 >= threshold=0.0100,等 loss 跌穿再触发)
[2026-06-16 04:06:13] [padp_for_test_train] [INFO] 未保存 score TopK ckpt
```

10D 跑 (loss ~ 0.005, 远 < 0.01 阈值), **epoch 0 ~ 30** loss 在 0.005 ~ 0.05 区间快速下降, **从 epoch ~ 5 起 loss 跌穿 0.01 阈值**:
- 运行记录.md 第 1193 行起打印 "Loss 历史": `epoch 0: loss=0.167199` → `epoch 4: 0.0093xxx` (跌穿 0.01 大约在 ep 4-5 附近)
- 所以 Phase 1→2 切换的 epoch 取决于 loss 跌穿 0.01 的时间点

### 4.2 Phase 2 rollout 触发条件

10D 跑 Phase 2 行为 (`/home/hy/Desktop/PADP_v3/运行记录.md` 第 978-985 行):
```
[2026-06-16 04:42:32] [padp_for_test_train] [INFO] Epoch 240/251: avg_loss=0.0046
[2026-06-16 04:42:32] [padp_for_test_train] [INFO] [Rollout] epoch=240 开始 server+client rollout...
[2026-06-16 04:43:33] [padp_for_test_rollout] [ERROR] [rollout] Server 在 60.0s 内未启动,放弃 rollout
[2026-06-16 04:43:33] [padp_for_test_train] [INFO] [Rollout ep=240] test_mean_score=0.0000
[2026-06-16 04:43:38] [padp_for_test_train] [INFO] [TopK] epoch=240 loss=0.0046 score=0.0000 phase=score (topk/loss + topk/score)
```

注意关键: **server 没启动 (60s timeout), 但 test_mean_score 被记成 0.0**, 然后 topk/score ckpt **被保存了**! 所以这是 "rollout 失败但 ckpt 仍然写入" 的行为。

### 4.3 epoch 30/35/40 vs epoch 5/10/15 差异

**问题核心**: 1.1_10D 的 score ckpt 是 epoch 5/10/15, 1.2_10D 的是 epoch 30/35/40。两者都是 Phase 2 的 score (test_mean_score=0), 间隔都是 5, 但是 **起始 epoch 完全不同**。

**答案**:
- 1.1_10D 的训练日志显示 Phase 2 触发的 epoch 起始是 epoch 5 (这是 BEST score 的 epoch, 即"第一次 score 触发并产生 0.0"的那个 epoch, 来自运行记录.md 第 230 行 `BEST score ckpt (Phase 2): score=0.000000 epoch=5`)
- 1.2_10D 的 BEST score epoch 是 30 (运行记录.md 第 1191 行 `BEST score ckpt (Phase 2): score=0.000000 epoch=30`)

**为什么 1.2_10D 从 epoch 30 开始**:
- 1.2_10D 跑 (1.2_lerobot_libero10d) 的训练 loss 历史 (来自运行记录.md 第 1193 行起的 Loss 历史) 显示 epoch 0 起 loss 就已经较低 (0.167 → 0.022 → 0.012 → 0.011 → 0.0099 → 0.0097, 到 epoch 5 已经在 0.0093 附近)
- Phase 2 触发 **要求 loss 跌穿 0.01 阈值** (`>= threshold=0.0100, 等 loss 跌穿再触发`, 见 7D 日志)
- 1.1_10D 是从 epoch 0 (loss 0.119) 启动后第 5 epoch loss 就跌穿 0.01, Phase 2 第一次触发在 epoch 5
- 1.2_10D 训练起点更优, **loss 在前 30 个 epoch 没真正"跌穿过"阈值过 (可能在 0.01 附近震荡, 训练代码里 phase 切换可能要求 "连续 N 个 epoch 都跌穿" 或者 "稳态 < 0.01")**, 直到 epoch 30 才满足切换条件

→ **epoch 30 不是"中断了才从 30 开始"**, 而是 Phase 1→2 切换点本身的 epoch 是 30。间隔 5 (5/10/15 vs 30/35/40) 是 rollout 频率 (interval=5) 决定的。

### 4.4 1.2_10D Phase 2 间隔 = 5

从运行记录.md 第 978, 1077, 1177 行:
- epoch 240 触发了 rollout (Phase 2)
- epoch 245 触发了 rollout (240 + 5)
- epoch 250 触发了 rollout (245 + 5)

→ Phase 2 rollout **严格按 5 epoch 一次**。所以 topk/score 也是按 5 epoch 存一个, 30/35/40 = 30 + 5*0 / 30 + 5*1 / 30 + 5*2。

→ **早期 (epoch 0~25) 没有 score ckpt 是因为 Phase 1 没结束, rollout 没跑**。这不是中断, 是 phase 切换规则。

## 5. 结论

### 5.1 epoch030_score0.0000.ckpt 是否完整?
**是, 完全完整**。
- ZIP 完整 (766 entry, testzip OK, no truncation)
- size 1,102,650,660 B 与兄弟 score ckpt (epoch035, epoch040) 字节级一致
- mtime 09:42 与 epoch035 / epoch040 完全相同, 没有任何 "写到一半被杀" 的迹象 (被杀的 ckpt mtime 会比正常的早, size 偏小)
- 内部包含完整 data.pkl + byteorder + 764 个 data tensor 段, 结构与 latest.ckpt 一致
- 大小 (1.1G) 与 latest.ckpt (1.1G) 在同一量级, 比例合理 (model state_dict 主导)

### 5.2 是否被中断?
**否**。证据:
1. size 1,102,650,660 B 与 epoch035 (1,102,650,660 B) / epoch040 (1,102,650,660 B) **完全相同**; 中断文件 size 会偏小
2. mtime 都在 09:42 同一秒, 跟其他兄弟 ckpt 一起完整写入
3. ZIP 自身未损坏 (testzip None)
4. 与 latest.ckpt 大小比例正常 (~1.0001x, 仅相差 766 B 字典字段差)
5. 整个 topk/ 目录 (score + loss 共 6 个文件) 都没有 "写一半被杀" 的痕迹
6. 运行记录.md 第 1191 行明确打印 `BEST score ckpt (Phase 2): score=0.000000 epoch=30 path=...epoch030_score0.0000.ckpt`, 即**训练脚本自己认为 epoch030 是合法 best score ckpt**

### 5.3 为什么 1.2_10D score 从 epoch 30 开始?
**Phase 1 → Phase 2 的切换点就是 epoch 30**。
- 1.1_10D (padp_for_test_golden): loss 起始 0.119, 跌穿 0.01 阈值在 epoch 5 附近 → Phase 2 起始 epoch 5 → score ckpt 5/10/15
- 1.2_10D (v1.2_lerobot_libero10d): loss 起始 0.167, **前 30 epoch 一直处于 Phase 1 (可能因为 loss 接近 0.01 但没稳定跌穿, 触发逻辑要求更严)**, 第 30 epoch 才正式切到 Phase 2 → score ckpt 30/35/40
- 1.2_7D (v1.2_lerobot_libero7d): loss 一直在 0.01 ~ 0.02 区间震荡, **整个 251 epoch 都没跌穿 0.01 阈值, 完全没有 Phase 2** → 没有任何 score ckpt (运行记录.md 第 1546 行: `未保存 score TopK ckpt`)

### 5.4 早期 epoch (0-25) 没 score ckpt 的原因
**Phase 1 没结束, rollout 没启动, 所以根本不会写 topk/score**。
- Phase 1 只保存 topk/loss (Top-K by loss)
- Phase 2 才同时保存 topk/loss 和 topk/score (Top-K by score, 触发条件 = loss 稳定 < 0.01)
- 1.2_10D 的 Phase 1 持续了 30 个 epoch, 所以前 30 epoch 只有 loss ckpt
- 1.1_10D 的 Phase 1 持续了 5 个 epoch, 所以前 5 epoch 只有 loss ckpt (但 1.1_10D 早期 loss ckpt 在本机 data/data/ 下没拷过来, 只看到 246/247/250 这几个, 实际服务器应该有 0-25 的 loss ckpt)

### 5.5 rollout 频率 / interval
- **Phase 2 rollout 严格按 interval=5 触发**: ep 240, 245, 250 各跑一次
- 1.1_10D: ep 5, 10, 15 (实际跑过, 但 240/245/250 的 score 都 0.0 没保存, 因为已经是 best)
- 1.2_10D: ep 30, 35, 40 (实际跑过, 同理 240/245/250 跑过但 score 0.0 没覆盖 best)
- "实际跳到 30" 是 Phase 1 长度决定的 (1.2_10D 的 loss 下降更慢或触发条件更严, 导致 Phase 1 持续更久), **不是被中断**

### 5.6 关于"epoch 30 之前 score=0.0"的疑问
- epoch 30 是 Phase 2 第一次 rollout 成功的 epoch (BEST 落在这里)
- 1.2_10D 的 240/245/250 也都跑了 rollout, 但 score 同样是 0.0, 没有更新 BEST (因为 best 还是 0.0, 不更新)
- 0.0 反映 "rollout server 启动失败, 60s timeout, fallback 0.0" 的现象 (运行记录.md 第 981-982 行): `[ERROR] [rollout] Server 在 60.0s 内未启动,放弃 rollout` → `[Rollout ep=240] test_mean_score=0.0000`
- 这与 1.1_10D 形成对比: 1.1_10D server 启动正常 (4 秒就绪), score 是真实 rollout 跑出来的 0.0 (可能是 evaluation task 太难, 跑 50 个 episode 一个都没成功)
