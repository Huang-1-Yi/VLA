## 一、7-Layer 顶级规则

### 1.1 七大层级定义

| 层级 | 名称 | 职责 | 不知道什么 |
|---|---|---|---|
| **A_common** | 基础设施层 | **5 个接口契约**(`BasePolicy` / `VisionEncoderInterface` / `ActionEncoderInterface` / `TimestepEncoderInterface` / `DiffusionNetworkInterface`)+ 数据结构 + 注册表 + IPC + Logger + Dataset 基类 | 任何业务,任何具体模型,任何具体硬件,任何具体算法 |
| **B_model** | 纯算力层 | **5 类 nn.Module 零件**:Encoders(VM/AM/TM)+ Networks(DM)+ **Adapters**(`<algo>_adapter.py`,实例化 VM/AM 并做特征融合投影);每个零件独立 `nn.Module`,只实现 `forward` + `output_shape` | **不定义 Policy 类**;不写训练/推理逻辑、不含 loss/scheduler/EMA/normalizer 注入;**不知道策略大脑的存在** |
| **C_sim** | 仿真边界 | 感官四肢(虚拟)。对接 mujoco / gym / Isaac;**对外仅暴露 `__init__.py` 的 factory**,内部 env_impl / runner / dataset 不被外部直接 import | 神经网络结构、训练逻辑、YAML 格式 |
| **D_real** | 真机边界 | 感官四肢(物理)。对接 libfranka / Realsense SDK;同 C_sim,对外走 factory | 同 C_sim |
| **E_cti** | **纯白痴执行台** | 控制台。读 YAML、起进程、跑主循环;**只能**通过 `build_policy(cfg.policy)` 拿到 Policy 实例,调 `policy.compute_loss(batch)` 和 `policy.predict_action(obs)` 即可;**不知道 scheduler / 加噪 / loss / denoise loop 是什么**;**不准 import 任何 `B_model.*` 内部符号** | 类设计、算法逻辑、模型实现、scheduler |
| **F_envs** | 环境管理 | **纯 conda 路线**(弃 uv),所有依赖收口到单一 `environment.yml`(Python 包走文件内 `pip:` 段);**独立模块,不依赖任何其他字母** | 任何代码 |
| **G_policy** | **策略大脑(Fat Policy)层** | **每种算法一个子包**(DP / PADP / SDP / ...),子包内含 `<algo>_policy.py`(**Fat Policy,继承自 `A_common.types.base_policy.BasePolicy`**,`__init__` 里**实例化** Adapter + TM + DM;暴露 `compute_loss` 和 `predict_action` 两个高层方法;内部精细化调度 scheduler / 加噪 / loss 加权 / denoise loop)+ `<algo>_pipeline.py`(可选用工具函数,如 loss_weights)+ `common/denoise_loop.py`(跨算法共享的 DDIM 推理模板) | 真机 SDK 细节、采集 UI、YAML 格式 |

> **关键事实(从 [接口契约 §一](落地方案v4-1的接口契约.md#一调用流为什么需要这-5-个接口) 反向推导)**:
> - **E_cti = 纯白痴执行台** —— 不管训练还是推理,都把数据当黑盒抛给大脑,不碰 scheduler / 加噪 / 权重
> - **G_policy = 策略大脑(Fat Policy)** —— 继承自 `BasePolicy`(即 `nn.Module`);掌控 `__init__` 选配模型、实例化 Adapter / TM / DM;**亲手接管** scheduler 实例化 / 加噪 / loss 加权 / denoise loop
> - **B_model = 纯算力层** —— 只装 VM / AM / TM / DM 和 Adapter(纯 `nn.Module`),**无策略调度概念**

### 1.2 单向依赖的传递性

```
E_cti  →  G_policy  ──→  A_common
   │       │              ↑
   │       │              │  (G_policy 实例化 B_model 的 nn.Module 进 Policy)
   │       └────────────► B_model  ──→  A_common
   │                       (G_policy 在 __init__ 里 import B_model 的具体类)
   ↓
C_sim / D_real  ──→  A_common

F_envs:独立(只被 conda 引用,不 import 任何其他字母)
```

| 模块 | 允许 import | 严禁 import |
|---|---|---|
| **A_common** | `torch`, `numpy`, 任何第三方 | B/C/D/E/G(它最底) |
| **B_model** | A_common、torch、transformers、第三方 | C/D/E/G(**不知道策略大脑的存在**) |
| **C_sim** | A_common、mujoco、gym、torch、第三方 | B/D/E/G |
| **D_real** | A_common、libfranka、pyrealsense2、torch、第三方 | B/C/E/G |
| **E_cti** | A/B/C/D/F/G(任意)+ 第三方 | **❌ 不准 import `B_model.*` 内部符号**(铁律 1 强化版) |
| **F_envs** | 第三方(只是 yaml) | A/B/C/D/E/G |
| **G_policy** | A_common(含 5 个接口契约)、B_model(G_policy 在 `__init__` 里 import 具体类,**不是 B_model 来找 G_policy**)、C/D(可选)、torch | E(**不准被 E_cti import 内部细节,只能 `build_policy()` 拿接口**) |

> **C/D 不进 B_model**:B_model 是网络,不知道真机/仿真。C/D 写各自的 `adapter.py` 把硬件数据 → A_common 的 ObsDict。
>
> **B_model 不定义 Policy**:Policy 类在 G_policy 下,G_policy 实例化 B_model 的 nn.Module 拼装成 Policy。所以 G_policy `import B_model` 是允许的,B_model 没有任何代码 `import G_policy` —— 这从结构上就杜绝了反向依赖。

## 二、7 条铁律(强化版)

任何代码 commit 前必过。

> **铁律 1:`E_cti` 不许写 `class`,只写执行脚本;且 E_cti 是"纯白痴",只能调 `policy.compute_loss(batch)` / `policy.predict_action(obs)`**
>
> ```python
> # ✅ 正确(E_cti 调策略大脑)
> if __name__ == "__main__":
>     cfg = load_yaml(...)
>     algorithm = build_policy(cfg.policy)   # 拿到 Fat Policy 实例
>     for batch in dataloader:
>         loss = policy.compute_loss(batch)      # E_cti 拿回标量 loss
>         loss.backward(); optim.step()
>     for obs in env:
>         action = policy.predict_action(obs)    # E_cti 拿回 ActionOutput
>         env.step(action.actions)
>
> # ❌ 错误
> class Workspace: ...                               # 铁律 1-1: E_cti 无 class
> class EvalSimRunner: ...                           # 铁律 1-1
> for t in scheduler.timesteps: ...                  # 铁律 1-2: E_cti 不准出现 scheduler
> loss = MSE(...) * weights                          # 铁律 1-2: E_cti 不准算 loss
> policy.dm(a_t, t, cond)                           # 铁律 1-3: E_cti 不准穿透 Policy 内部
> ```
>
> **铁律 1 强化版**(3 条):
> 1. **无 class**:E_cti 内所有文件无 `class Xxx`,只放 `if __name__ == "__main__"` 脚本
> 2. **无算法概念**:E_cti 出现 `add_noise` / `loss_weights` / `DDIMScheduler` / `MSE` / `F.mse_loss` 字样的代码,即为违规
> 3. **不穿透 Policy 内部**:E_cti 出现 `policy.vm.` / `policy.dm.` / `policy.adapter.` 字样,即为违规
>
> **自动化检查**:
> ```bash
> # 铁律 1-1: E_cti 无 class
> [ -z "$(grep -rE '^class ' E_cti/)" ] && echo "OK 1-1" || echo "FAIL 1-1"
>
> # 铁律 1-2: E_cti 不准出现 scheduler / 加噪 / loss 算子
> [ -z "$(grep -rE 'add_noise|loss_weights|DDIMScheduler|F\.mse_loss|MSELoss' E_cti/)" ] && echo "OK 1-2" || echo "FAIL 1-2"
>
> # 铁律 1-3: E_cti 不准穿透 Policy 内部(只能调 .compute_loss / .predict_action / .set_normalizer / .reset)
> [ -z "$(grep -rE 'policy\.(vm|am|tm|denoiser|dm|adapter|_normalizer)\.' E_cti/)" ] && echo "OK 1-3" || echo "FAIL 1-3"
> ```

> **铁律 2:`B_model` 只放纯算力零件(Encoders / Networks / Adapters);不定义 Policy 类、不写训练/推理逻辑**
>
> `B_model` 下每个文件是**独立的 `nn.Module`**,只实现 `forward` + `output_shape`(DM 还可以加 `shape_info()`)。
> **Policy 类**(继承 `A_common.types.base_policy.BasePolicy`、持有算法专属 buffer、暴露 `compute_loss` / `predict_action`)**归 `G_policy/<algo>/<algo>_policy.py`**。
> 任何"我要在 B_model 里加 policy / 推理循环 / loss"的想法都应移到 G_policy。

> **铁律 3:数据结构 + 5 个协议/接口抽象一律进 `A_common/types/`**
>
> `ActionOutput`、`Observation`、`State`、`Normalizer` 等 dataclass,以及 5 个 abstract class(VM/AM/TM/DM/BasePolicy),均放 `A_common/types/`。
> 其他层**只 import,不定义**。

> **铁律 4:`C_sim` / `D_real` 对外只暴露 factory,不暴露内部实现**
>
> `E_cti` / 其它层**只能** `import C_sim` 然后调 `C_sim.make_eval_runner(cfg)` 之类的工厂方法。
> **禁止** 直接 `from C_sim.robomimic.env_runner import RobomimicImageRunner`。
> `C_sim/__init__.py` 是唯一对外入口,内部 `env_impl / env_runner / dataset` 是私有细节。

> **铁律 5:`G_policy/common/denoise_loop.py` 接受 scheduler 作为参数**
>
> denoise loop **不得**在内部 `import DDIMScheduler` 或 `DDIMScheduler(...)` 硬编码实例化。
> 调用方在 `DP/dp_policy.compute_loss` / `PADP/padp_policy.compute_loss` 中**各自实例化**自己的 scheduler 后,作为参数传入。
> 这样 denoise loop 完全无状态、可独立单测、可被任意调度器替换。

> **铁律 6:`A_common/data/base_dataset.py` 显式声明 `n_obs_steps` 与 `horizon`**
>
> 数据集时序契约是 7-Layer 架构的"硬约定":
> - `n_obs_steps`:历史观测窗口长度
> - `horizon`:未来动作块长度
>
> 所有 `BaseVLADataset` 派生类(robomimic zarr / 真实 Realsense / LeRobot 等)必须:
> - 在 `__init__` 接收这两个参数并暴露为类属性
> - 返回的 `action` shape 严格对齐 `[horizon, D_a]`
> - episode 首尾 padding 在派生类(各 sim 的 dataset)内处理,**不能**要求 E_cti 兜底

> **铁律 7:`F_envs` 走纯 conda 路线,弃 uv 与 requirements.txt**
>
> 所有依赖收口到 `F_envs/base_train/environment.yml` 一个文件。
> - 系统级 / 二进制:走 conda channels(`pytorch`, `nvidia`, `conda-forge`)
> - Python 包:走文件内 `pip:` 段(不另开 `requirements.txt`)
> - 完整命令:`conda env create -f F_envs/base_train/environment.yml`

### 2.1 为什么是这 7 条?(架构动机)

- **铁律 1** 是 v5 相对 v4 的**核心强化**:v4 的 E_cti 知道 scheduler / loss / denoise loop(因为 `compute_loss` 是 G_policy 自由函数,E_cti 需要在训练 loop 里手动调度),这导致 E_cti 不是"纯白痴"。v5 让 E_cti 只调 2 个高层方法,所有算法知识封死在 Policy 类里
- **铁律 2** 保持 v4 的"Policy 类归 G_policy"原则,但 v4 是 thin Policy(v4 文档 v1.1 那种:Policy 只暴露 `forward(a_t, t, encoded)`,G_policy 自由函数调它),v5 升级为 **Fat Policy**(Policy 自己 `__init__` 装配、自己 `compute_loss` / `predict_action`,不再需要 G_policy 自由函数)
- **铁律 3** 强化 5 个 abstract class 都进 A_common(此前 v4 漏了 VM/AM/TM/DM 这 4 个,只在 B_model/encoders/.../interface.py 里)
- **铁律 4-7** 与 v4 一致

## 三、5 个接口契约(总览)

> **完整模板契约见 [落地方案v4-1的接口契约.md §二](落地方案v4-1的接口契约.md#二5-个接口的模板契约)**(本节不重复,只列定位)

5 个 abstract class 的归属与位置:

| 接口 | 位置 | 职责 | 关键方法 | 状态 |
|---|---|---|---|---|
| `VisionEncoderInterface` | `A_common/types/vision_encoder.py` | 图像编码器(VM) | `forward(obs_dict) → Tensor` + `output_shape()` | v5 新增 |
| `ActionEncoderInterface` | `A_common/types/action_encoder.py` | 历史动作编码器(AM) | `forward(action_seq) → Tensor` + `output_shape()` | v5 新增 |
| `TimestepEncoderInterface` | `A_common/types/timestep_encoder.py` | 扩散时间步编码器(TM) | `forward(t) → Tensor` + `output_shape()` | v5 新增 |
| `DiffusionNetworkInterface` | `A_common/types/diffusion_network.py` | 动作去噪网络(DM) | `forward(sample, **cond) → Tensor` + `output_shape()` + 推荐 `shape_info()` | v5 新增 |
| `BasePolicy` | `A_common/types/base_policy.py` | **策略大脑契约(Fat Policy)** | `forward(a_t, t, global_cond) → Tensor` + `compute_loss(batch) → Tensor` + `predict_action(obs) → ActionOutput` + `reset()` + `set_normalizer()` + 推荐 `shape_info()` | v5/v7 新增 `forward`(单步 DM 封装) |

### 3.1 5 个接口的方法对照(从 [接口契约 §三](落地方案v4-1的接口契约.md#三五-个接口的方法对照一张表说清楚) 复用)

| 接口 | forward | output_shape | shape_info | compute_loss | predict_action |
|---|---|---|---|---|---|
| **VM/AM/TM** | ✅ 必须 | ✅ 必须 | — | — | — |
| **DM** | ✅ 必须 | ✅ 必须 | 🔶 推荐 | — | — |
| **BasePolicy** | **✅ 必须(单步 DM 封装)** | — | — | **✅ 必须** | **✅ 必须** |

> 注:BasePolicy 的 `forward(a_t, t, global_cond)` 是"单步 DM 封装",由 `compute_loss` / `predict_action` 内部调用(后者在 denoise loop 中反复调),**不直接面向 E_cti**——E_cti 只调 `compute_loss` / `predict_action` 两个高层入口。

**规律**:
1. 纯算力零件(VM/AM/TM/DM)只有 `forward` + `output_shape`
2. 策略大脑(BasePolicy)必须实现 3 个方法:`forward`(单步 DM 封装) + `compute_loss`(训练高层入口) + `predict_action`(推理高层入口),对外屏蔽所有模型组合与调度的细节

### 3.2 调用流与接口对照(从 [接口契约 §四](落地方案v4-1的接口契约.md#四调用流与接口对照防止接口与现实脱节) 复用)

每一行 = 接口方法 → 谁会调它 → 调来干什么:

| 方法 | 谁调 | 干什么 |
|---|---|---|
| `vm.forward(obs_dict)` | G_policy Policy 在 `compute_loss` / `predict_action` 里调 | 提图像特征 |
| `am.forward(action_seq)` | G_policy Policy | 提历史动作嵌入 |
| `tm.forward(t)` | G_policy Policy | 提时间步嵌入 |
| `dm.forward(sample, **cond)` | G_policy Policy 的 denoise loop 里 | 单步去噪预测 |
| `adapter.forward(obs)` | G_policy Policy | 把 VM/AM/TM 输出融合投影为 global_cond |
| `policy.compute_loss(batch)` | **E_cti** | 拿回标量 loss |
| `policy.predict_action(obs)` | **E_cti** | 拿回 ActionOutput |
| `policy.reset()` / `set_normalizer(n)` | E_cti 在 episode 切换 / 推理前调 | 状态重置 + 注入 normalizer |

## 四、调用流(Fat Policy 视角)

> **完整调用流图见 [落地方案v4-1的接口契约.md §一](落地方案v4-1的接口契约.md#一调用流为什么需要这-5-个接口)**(权威)。本节给出文本化简版。

### 4.1 E_cti 训练 loop(纯白痴)

```python
# E_cti/train/run_train.py
if __name__ == "__main__":
    cfg = load_yaml("E_cti/configs/train_padp.yaml")
    algorithm = build_policy(cfg.policy)  # 拿到 Fat Policy 实例
    for batch in dataloader:                    # batch 已归一化
        loss = policy.compute_loss(batch)    # ⭐ E_cti 唯一要做的
        loss.backward(); optim.step()
```

### 4.2 E_cti 评估 loop(纯白痴)

```python
# E_cti/train/run_eval.py
if __name__ == "__main__":
    cfg = load_yaml("E_cti/configs/train_padp.yaml")
    algorithm = build_policy(cfg.policy)
    algorithm.load_state_dict(torch.load(cfg.eval.ckpt_path))
    runner = C_sim.make_eval_runner(cfg.env_meta)
    metrics = runner.run(policy.predict_action)  # ⭐ E_cti 把 predict_action 当 callable 传给 runner
```

### 4.3 G_policy Fat Policy(策略大脑)

```python
# G_policy/PADP/padp_policy.py
class SlidingWindowDiffusionPolicy(BasePolicy):
    def __init__(self, cfg):
        super().__init__()
        # ===== 算力零件装配(B_model 组件)=====
        self.adapter = PADPAdapter(cfg)  # B_model/adapters/padp_adapter.py(包含 VM/AM/fusion)
        self.tm = SinusoidalTimestepEncoder(cfg)  # B_model/encoders/TM/sinusoidal.py
        self.denoiser = Unet1DPadp(cfg)  # B_model/networks/DM/unet1d_padp.py

        # ===== 调度器一次性实例化(Fat Policy 设计:scheduler 不在方法体内每次重建)=====
        self.train_scheduler = DDIMScheduler(
            num_train_timesteps=cfg.scheduler.num_train_timesteps,
            beta_schedule=cfg.scheduler.beta_schedule, ...)
        self.infer_scheduler = DDIMScheduler(
            num_train_timesteps=cfg.scheduler.num_train_timesteps,
            beta_schedule=cfg.scheduler.beta_schedule, ...)

        # ===== 维度缓存(供 predict_action 初始噪声用)=====
        self.horizon = cfg.policy.horizon
        self.action_dim = cfg.policy.action_dim

    def forward(self, a_t, t, global_cond):
        # 单步 DM 封装(供 compute_loss / predict_action 内部调用)
        encoded_t = self.tm(t)
        return self.denoiser(a_t, global_cond=global_cond, encoded_t=encoded_t)

    def compute_loss(self, batch):
        # 1. 采 t / 加噪(复用 __init__ 实例化的 scheduler)
        a0 = batch["action"]  # [B, H, D_a]
        t = torch.randint(0, self.train_scheduler.config.num_train_timesteps, (a0.shape[0],))
        noise = torch.randn_like(a0)
        a_t = self.train_scheduler.add_noise(a0, noise, t)
        # 2. 提特征(1 次,不在 loop 里)
        global_cond = self.adapter(batch["obs"])
        # 3. 调 DM 前向
        pred_noise = self.forward(a_t, t, global_cond)
        # 4. 加权 MSE(PADP 特有,per-horizon 权重 w 形状 [H],广播为 [1, H, 1])
        w = get_loss_weights(self.horizon, decay=cfg.padp.decay, alpha=cfg.padp.alpha)
        # loss 公式:对 (B, H, D_a) 元素先平方,再与 w 广播相乘,最后 mean 出 scalar
        return ((pred_noise - noise) ** 2 * w[None, :, None]).mean()

    def predict_action(self, obs) -> ActionOutput:
        # 1. 循环外提 1 次特征(性能关键!)
        global_cond = self.adapter(obs)
        # 2. Denoise Loop(复用 __init__ 实例化的 scheduler)
        a = torch.randn(obs.shape[0], self.horizon, self.action_dim,
                        device=self.device, dtype=self.dtype)
        for t in self.infer_scheduler.timesteps:
            pred_noise = self.forward(a, t, global_cond)
            a = self.infer_scheduler.step(pred_noise, t, a).prev_sample
        # 3. 反归一化
        action = self._normalizer["action"].unnormalize(a)
        return ActionOutput(actions=action, is_chunk=True, latency_ms=...)
```

### 4.4 B_model Adapter(特征融合器)

```python
# B_model/adapters/padp_adapter.py
class PADPAdapter(nn.Module):           # 类名按 v7 契约:驼峰,PADP + Adapter
    def __init__(self, cfg):
        super().__init__()
        # 实例化 VM(从 B_model/encoders/VM/ 选具体实现)
        self.vm = build_vision_encoder(cfg)        # ResNet18 / DINOv2 等
        # 实例化 AM
        self.am = build_action_encoder(cfg)        # Conv1d embed 等
        # 特征融合 MLP
        self.fusion_network = FeatureFusionMLP(cfg)

    def forward(self, obs) -> condition:
        encoded_v = self.vm(obs["image"])
        encoded_a = self.am(obs["action_history"])
        return self.fusion_network(encoded_v, encoded_a)
```

### 4.5 关键事实

- **E_cti 是纯白痴执行台** —— 训练 `loss = policy.compute_loss(batch)`,推理 `action = policy.predict_action(obs)`,**不碰 scheduler / 加噪 / 权重**
- **G_policy 是策略大脑(Fat Policy)** —— 继承自 `BasePolicy`(即 `nn.Module`);`__init__` 选配模型、实例化 Adapter / TM / DM;**亲手接管** scheduler 实例化 / 加噪 / loss 加权 / denoise loop
- **B_model 是纯算力层** —— 只装 VM / AM / TM / DM 和 Adapter(纯 `nn.Module`),**无策略调度概念**

| 维度 | v4(**已被推翻**) | v5(**终极白盒架构,v7 强化**) |
|---|---|---|
| **Policy 类形态** | Thin 容器(只暴露 `encode_inputs` / `forward`) | **Fat 策略大脑**(`__init__` 装配 + 缓存 scheduler + 缓存维度,暴露 **3 个方法**:`forward` / `compute_loss` / `predict_action`) |
| **Policy 类位置** | `G_policy/<algo>/<algo>_policy.py` | `G_policy/<algo>/<algo>_policy.py`(同位置,内容升级) |

| **铁律 3** | "数据结构在 A_common/types/" | 强化:**含 5 个 abstract class** |
