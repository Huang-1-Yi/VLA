## 一、调用流(为什么需要这 5 个接口)

```python
注意：VM、AM、TM、adapters、DM文件夹全部都在B_model文件夹下面各自一个文件夹，config可以指定它们具体用哪一个。 

E_cti/train/run_train.py (纯白痴执行台，绝不碰任何具体策略细节)
    └─ if __name__ == "__main__":
        │    ├─ config["policy"]["name"] = "PADP_policy"
        │    └─ config["training"] = {lr, batch_size, ...}
        │
        ├─ 实例化策略大脑 (根据 config)
        │    └─ policy = build_policy(cfg.policy) 
        │         # 内部会自动实例化 SlidingWindowDiffusionPolicy
        │         # 大脑内部会自动装配好 VM, AM, TM, DM 和 Adapter
        │
        └─ 训练 loop:
             for batch in dataloader:    # batch是归一化的
                 # ⭐️ 核心：E_cti 把数据(batch)丢进policy去，直接拿回标量 loss！
                 # 不加噪、不管 scheduler、不配权重、不亲自算 loss！
                 loss = policy.compute_loss(batch)
                 loss.backward(); optim.step()



================================================================================



B_model/adapters/PADP_adapter.py (专职提特征与融合：先后调用VM 等各种编码器提batch中的各种特征，最后投影为条件global_cond)
    └─ class PADPAdapter(nn.Module):
        ├─ def __init__(self, cfg):
            ├─ self.vm = VM(cfg) # 冻结 B_model/encoders/VM/
            │     └─ vm.output_shape()  ← 算出特征维度
            ├─ self.am = AM(cfg) # 冻结 B_model/encoders/AM/
            │     └─ am.output_shape()  ← 算出动作嵌入维度
            ├─ self.fusion_network = FeatureFusionMLP (cfg) # B_model/adapters/
                  └─ 把 VM/AM 输出投影到 DM 期望的global_cond
        └─ def forward(self, obs) -> condition:
            ├─ encoded_v1 = self.vm(obs["img1"])
            ├─ encoded_v2 = self.vm(obs["img2"])
            ├─ encoded_a = self.am(obs["action_history"])
            └─ return self.fusion_network(encoded_v1, encoded_v2, encoded_a) # 不同的adapter使用的方法不同

================================================================================

G_policy/PADP/PADP_policy.py (策略大脑，接管扩散模型的所有脏活)
    └─ class SlidingWindowDiffusionPolicy(BasePolicy): 
        ├─ def __init__(self, cfg):
        │   super().__init__()  # 继承 BasePolicy.__init__,初始化 self._normalizer = None
        │   ├─ # ===== 算力零件装配(B_model 组件)=====
        │   ├─ self.adapter = PADPAdapter(cfg) # 包含了 VM, AM, fusion_network
        │   ├─ self.tm = TM(cfg) # B_model/encoders/TM/
        │   │     └─ tm.output_shape()  ← 算出时间嵌入维度
        │   ├─ self.dm = DM(cfg) # B_model/networks/DM/
        │   │     └─ 把 global_cond 输出为噪声或动作
        │   │
        │   ├─ # ===== 调度器一次性实例化(Fat Policy 设计:scheduler 不在方法体内每次重建)=====
        │   ├─ self.train_scheduler = DDIMScheduler(
        │   │       num_train_timesteps=cfg.scheduler.num_train_timesteps,
        │   │       beta_schedule=cfg.scheduler.beta_schedule,
        │   │       ...)
        │   ├─ self.infer_scheduler = DDIMScheduler(
        │   │       num_train_timesteps=cfg.scheduler.num_train_timesteps,
        │   │       beta_schedule=cfg.scheduler.beta_schedule,
        │   │       ...)
        │   ├─ # ===== 维度缓存(供 predict_action 初始噪声用)=====
        │   ├─ self.horizon = cfg.policy.horizon
        │   ├─ self.action_dim = cfg.policy.action_dim
        │
        ├─ def forward(self, a_t, t, global_cond): # global_cond指导DM预测数据
        │   ├─ encoded_t = self.tm(t)
        │   └─ return self.dm(a_t, global_cond=global_cond, encoded_t=encoded_t)
        │
        ├─ def compute_loss(self, batch):
        │   │
        │   ├─ 输入的加噪逻辑
        │   │   ├─ 获取 a0 = batch["action"] # [B, H, D_a] 干净动作
        │   │   ├─ 采样 t = torch.randint(0, self.train_scheduler.config.num_train_timesteps, (a0.shape[0],)) # (0, T, (B,))
        │   │   ├─ 生成噪声 noise = torch.randn_like(a0)
        │   │   └─ 加噪 a_t = self.train_scheduler.add_noise(a0, noise, t)  # 复用 __init__ 实例化的 scheduler
        │   │
        │   ├─ 调 B_model 的网络零件(仅 1 次提特征,不进 loop):
        │   │   ├─ global_cond = self.adapter(batch["obs"])
        │   │   └─ pred_noise = self.forward(a_t, t, global_cond)  # B_model/networks/DM 单步前向
        │   │
        │   ├─ 计算损失 Loss:
        │   │   ├─ w = get_loss_weights(self.horizon, decay=cfg.padp.decay, alpha=cfg.padp.alpha) # PADP 特有
        │   │   └─ loss = loss = ((pred_noise - noise) ** 2 * w[None, :, None]).mean() # MSE(pred_noise, noise) * w, horizon维度的变化，其它维度相同
        │   │
        │   └─ return loss (返回给 E_cti)
        │
        └─ def predict_action(self, obs) -> ActionOutput:
            │
            ├─ 策略核心：Denoise Loop (扩散模型独有)
            │    ├─ 生成随机初始噪声 a_t = torch.randn(
            │    │       batch_size, self.horizon, self.action_dim,  # 维度从 __init__ 缓存
            │    │       device=self.device, dtype=self.dtype)
            │    ├─ global_cond = self.adapter(obs)  # 循环外提特征,确保推理极速!
            │    └─ for t in self.infer_scheduler.timesteps:  # 复用 __init__ 实例化的 scheduler
            │           # DM 纯前向预测噪声 (B_model 网络只负责算,不知道什么是 step)
            │           pred_noise = self.forward(a_t, t, global_cond)
            │           a_t = self.infer_scheduler.step(pred_noise, t, a_t).prev_sample
            │
            ├─ 动作后处理:
            │    └─ action = self._normalizer["action"].unnormalize(a_t)  # 反归一化(用 set_normalizer 注入的)
            │
            └─ 返回统一契约格式:
                return ActionOutput(actions=action)

================================================================================

E_cti/train/run_eval.py (纯白痴执行台，绝不碰任何具体策略细节)
    └─ if __name__ == "__main__":
        ├─ 读 config.yaml
        │    ├─ config["policy"]["name"] = "PADP_policy"
        │    └─ config["eval"] = {ckpt_path, num_steps, ...}
        │
        ├─ 实例化 runner = C_sim.make_eval_runner(cfg.env_meta) # 隐藏仿真引擎细节
        │
        ├─ 实例化与训练时完全一致的策略大脑 (包含所有底层模型)
        │    └─ policy = build_policy(cfg.policy) 
        │              ├─ 内部自动实例化并组装好 PADP_adapter (含 VM, AM)、TM、DM
        │
        ├─ 加载权重 (Checkpoint)
        │    └─ policy.load_state_dict(torch.load(ckpt_path)) # ⭐️ 策略大脑接管了所有网络零件，直接 load 即可
        │
        └─ 评估 loop (runner.run 内部逻辑):
             for obs in env:
                 # 核心：E_cti 纯黑盒调用 policy，拿回动作！
                 # E_cti 绝对不写 Denoise 循环，不配推理 scheduler！
                 action_out = policy.predict_action(obs)
                 env.step(action_out.actions)
```

**关键事实**:
- **E_cti 是"纯白痴执行台"**——无论是训练 loop loss = policy.compute_loss(batch) 还是推理 loop action = policy.predict_action(obs)，它都把数据当黑盒抛给大脑，不碰 scheduler / 加噪 / 权重。
- **G_policy 是"策略大脑 (Fat Policy)"**——继承自 BasePolicy（即 nn.Module）。它掌控着 __init__ 选配模型，实例化 Adapter / TM / DM，并亲手接管 scheduler 实例化 / 加噪 / loss 加权 / denoise loop 等所有控制流。
- **B_model 是"纯算力层"**——只装 VM / AM / TM / DM 和特征投影 Adapter（纯 nn.Module 结构，无策略调度概念）。

## 二、5 个接口的"模板契约"

每个接口的写法遵循 `BaseDataset` 风格:
- `__init__` 留空壳,子类必须 `super().__init__()`
- 必须实现的方法用 `raise NotImplementedError()` 占位
- 可选方法提供默认实现

---

### 2.1 `VisionEncoderInterface`——图像编码器(VM)

```python
class VisionEncoderInterface(nn.Module):
    """图像编码器。输入 lerobot 标准图像 obs,输出特征 Tensor。
    Policy 在 __init__ 时调 output_shape() 决定 adapter 维度。"""

    def __init__(self):
        super().__init__()  # 子类继续 super().__init__() 完成参数注册

    # ---- 必须实现 ----
    def forward(self, obs_dict: dict) -> torch.Tensor:
        """输入图像 obs(lerobot 标准),输出特征 Tensor。"""
        raise NotImplementedError()

    def output_shape(self) -> tuple:
        """返回编码后特征 shape。"""
        raise NotImplementedError()
```

**为什么是这两条**:
- `forward`:每个编码器的本职——吃 obs 吐 feature
- `output_shape`:Policy 不知道 VM 输出几维(不同 backbone 维度不同),必须**反问**

**为什么没有更多**:
- 不需要 `input_shape`:输入是 lerobot 标准 obs_dict,Policy 知道怎么喂
- 不需要 `loss` / `reset`:VM 是无状态特征提取器

---

### 2.2 `ActionEncoderInterface`——历史动作编码器(AM)

```python
class ActionEncoderInterface(nn.Module):
    """历史动作序列编码器。"""

    def __init__(self):
        super().__init__()

    def forward(self, action_seq: torch.Tensor) -> torch.Tensor:
        """输入 [B, T, D_a] 历史动作,输出嵌入。"""
        raise NotImplementedError()

    def output_shape(self) -> tuple:
        raise NotImplementedError()
```

**为什么是这两条**:与 VM 同理——forward 是本职,output_shape 是 Policy 反查维度的入口。

---

### 2.3 `TimestepEncoderInterface`——时间步编码器(TM)

```python
class TimestepEncoderInterface(nn.Module):
    """扩散时间步编码器。"""

    def __init__(self):
        super().__init__()

    def forward(self, t: torch.Tensor) -> torch.Tensor:
        """输入 [B] 时间步,输出 [B, D_h] 嵌入。"""
        raise NotImplementedError()

    def output_shape(self) -> tuple:
        raise NotImplementedError()
```

**为什么是这两条**:与 VM/AM 同理。

**未来扩展**:语言编码器 / 触觉编码器等任何"输入 lerobot 标准 obs、输出维度对 Policy 未知"的组件,**统一继承这个模板**(`forward + output_shape`)。

---

### 2.4 `DiffusionNetworkInterface`——动作预测去噪网络(DM)

```python
class DiffusionNetworkInterface(nn.Module):
    """动作去噪网络。吃加噪动作 + 条件,吐去噪预测。
    DM 的 sample 输入/输出维度相同(D_a),由 __init__ 的 input_dim 决定。"""

    def __init__(self):
        super().__init__()
        # 子类继续:接收 input_dim / global_cond_dim / local_cond_dim 等参数,实例化 UNet / Transformer
        # 推荐在 __init__ 末尾 logger.info(self.shape_info()) —— 调试时一眼看清 DM 期望的形状

    # ---- 必须实现 ----
    def forward(self, sample: torch.Tensor, **cond) -> torch.Tensor:
        """输入加噪动作 [B, H, D_a] + 由 Adapter 投影好的全局条件，输出预测 [B, H, D_a]。"""
        raise NotImplementedError()

    def output_shape(self) -> tuple:
        """返回 sample 输入/输出的最后一维 (D_a,)。

        约定:
            forward 输入 sample 的 shape = [B, H, output_shape()[-1]]
            forward 输出的 shape     = [B, H, output_shape()[-1]]
        Policy 用它做 sanity check:assert adapter 输出 shape[-1] == dm.output_shape()[-1]
        """
        raise NotImplementedError()

    # ---- 推荐实现(非强制) ----
    def shape_info(self) -> str:
        """返回 DM 的形状摘要字符串,供调试时 __init__ 末尾 logger.info(...) 用。

        例:"sample=(10,), global_cond=(1536,), local_cond=None"
        """
        raise NotImplementedError()
```

**为什么有 `output_shape`**(与 VM/AM/TM 对齐):
- Policy 设计 adapter 时需要 sanity check:`assert adapter(vm_output).shape[-1] == dm.output_shape()[-1]`
- DM 的 `input_dim` 在 `__init__` 时确定,但暴露成方法后,Policy 不用记"DM 的输入维是 input_dim 还是别的属性名",统一 `dm.output_shape()[-1]`
- 未来如果 DM 变体(Transformer 输出 velocity 而不是 sample)有不同 shape,接口形态不变

**为什么 `forward` 不接 `t` 参数**:PADP 风格 UNet 不在网络内部用 t(噪声调度在 E_cti 用 scheduler 处理),`t` 在 `policy.predict_action_for_train` 里就用上了。但 `**cond` 必须保留——FiLM / cross-attn 都靠它注入。

**`shape_info()` 为什么是推荐而非必须**:
- 它只是一个"调试时打印用"的工具,不影响 forward 行为
- 不强制可以省掉一些 boilerplate,但建议每个具体 DM 都实现它(类似 `nn.Module.__repr__`)

### 2.5 `BasePolicy`——策略大脑契约 (G_policy 顶层接口)

```python
class BasePolicy(nn.Module):
    """所有策略大脑的统一基类(位于 G_policy)。
    它是包含了底层所有模型零件(Adapter/DM)以及策略调度逻辑(Scheduler/Loss)的超级模块。
    E_cti 只通过这个接口和整个系统交互。"""

    def __init__(self):
        super().__init__()
        self._normalizer = None
        # 在 __init__ 末尾 logger.info(self.shape_info())

    # ---- 必须实现(子类 override) ----
    def forward(self, a_t: torch.Tensor, t: torch.Tensor,
                global_cond: torch.Tensor) -> torch.Tensor:
        """DM 单步前向的封装,由 compute_loss / predict_action 内部调用。

        子类内部实现:
            encoded_t = self.tm(t)
            return self.dm(a_t, global_cond=global_cond, encoded_t=encoded_t)
        """
        raise NotImplementedError()

    def compute_loss(self, batch: dict) -> torch.Tensor:
        """接收 dataloader 吐出的 batch,执行前向传播和加噪,返回最终的标量 loss。
        E_cti 训练 loop 唯一入口:loss = policy.compute_loss(batch)"""
        raise NotImplementedError()

    def predict_action(self, obs: dict) -> ActionOutput:
        """接收实时 obs,执行 Denoise Loop 等推理逻辑,返回 ActionOutput 契约格式。
        E_cti eval/deploy 唯一入口:action_out = policy.predict_action(obs)"""
        raise NotImplementedError()

    # ---- 可选 override(基类给默认) ----
    def reset(self):
        """状态清空(默认无操作)。有状态 Policy(如 PADP 的 sliding window buffer)override。"""
        pass

    def set_normalizer(self, normalizer):
        """注入 normalizer(从数据集后算)。E_cti 推理前调一次。"""
        self._normalizer = normalizer

    # ---- 推荐实现(非必须) ----
    def shape_info(self) -> str:
        """返回 Policy 装配摘要(VM/AM/TM/DM 维度),供 __init__ 末尾 logger.info 用。"""
        raise NotImplementedError()
```

**E_cti ↔ G_policy ↔ B_model 三层的边界(v7)**:

```
E_cti 看到的:        policy.compute_loss(batch)   → 标量 loss
                    policy.predict_action(obs)   → ActionOutput
                    (E_cti 就像老板，按下一个按钮等结果)

G_policy 大脑做的:     实例化 scheduler / 采样 t / 加噪 / 加权 MSE
                    调 self.adapter(obs) 提特征 
                    调 self.dm(a_t, t, global_cond) 算预测
                    (G_policy 就像调度员，知道每一步该把数据派给哪个组件)

B_model 提供的:     VM / AM / TM / DM / Adapter (纯 nn.Module)
                    它们只实现 forward 和 output_shape
                    不包含任何控制流或去噪循环。
```

## 三、5 个接口的方法对照(一张表说清楚)

| 接口 | forward | output_shape | shape_info | compute_loss | predict_action |
|---|---|---|---|---|---|
| **VM/AM/TM** | ✅ 必须 | ✅ 必须 | — | — | — |
| **DM** | ✅ 必须 | ✅ 必须 | 🔶 推荐 | — | — |
| **BasePolicy** | ✅ 必须(单步 DM 封装) | — | — | ✅ 必须 | ✅ 必须 |

> 注:BasePolicy 的 `forward` 是"单步 DM 封装",由 `compute_loss` / `predict_action` 内部调用(后者在 denoise loop 中反复调),**不直接面向 E_cti**——E_cti 只调 `compute_loss` / `predict_action` 两个高层入口。

**规律**:
1. 纯算力零件(VM/AM/TM/DM)只有 `forward` + `output_shape`。
2. 策略大脑(BasePolicy)必须实现 3 个方法:`forward`(单步 DM 封装) + `compute_loss`(训练高层入口) + `predict_action`(推理高层入口),对外屏蔽所有模型组合与调度的细节。

## 四、调用流与接口对照(防止接口与现实脱节)

每一行 = 接口方法 → 谁会调它 → 调来干什么:
铁律强化版:

E_cti 不准穿透 Policy 内部: E_cti 的代码里只能出现 policy.compute_loss(batch) / policy.predict_action(obs)，绝对不能出现 policy.vm 或 policy.dm 的字眼。

G_policy 可以直接操控 B_model 零件: G_policy 内部必须显式调用 self.adapter(obs) 和 self.dm(...)。这是它的本职工作。
```python
# 自动检查 1:E_cti 不准穿透 Policy 内部
[ -z "$(grep -rE 'policy\.(vm|am|tm|adapter|dm)\.' E_cti/)" ] && echo "OK" || echo "FAIL"
# 自动检查 2:E_cti 不准出现 scheduler / loss_weights 字样
[ -z "$(grep -rE 'add_noise|loss_weights|DDIMScheduler' E_cti/)" ] && echo "OK" || echo "FAIL"
```

**铁律 2 强化版**:
- **E_cti 不准穿透 Policy 内部**:E_cti 的代码里**只能出现** `policy.compute_loss(batch)` / `policy.predict_action(obs)` / `policy.set_normalizer(...)` / `policy.reset()`,**不能出现** `policy.vm.xxx` / `policy.adapter.xxx` / `policy.dm.xxx`——Adapter / encoders / DM 是 Policy 的私有子组件
- **G_policy 的 Policy 实现类可以穿透自己内部**:Policy 自己的方法 `compute_loss` / `predict_action` / `forward` 内部**允许** `self.adapter(obs)` / `self.tm(t)` / `self.dm(a_t, t, global_cond)` / `self._normalizer["action"].unnormalize(...)`——Fat Policy 紧密耦合自身零件,这是它的工作
- **E_cti 是"纯白痴"**:它不需要知道 scheduler / 加噪 / loss / denoise loop 这些概念

```bash
# 自动检查 1:E_cti 不准穿透 Policy 内部
[ -z "$(grep -rE 'policy\.(vm|am|tm|denoiser|dm|_normalizer)\.' E_cti/)" ] && echo "OK" || echo "FAIL"
# 自动检查 2:E_cti 不准出现 scheduler.add_noise / loss_weights / DDIMScheduler 字样
[ -z "$(grep -rE 'add_noise|loss_weights|DDIMScheduler' E_cti/)" ] && echo "OK" || echo "FAIL"
```

## 五、AI写作的反复教训(避免下次再走错方向)

当前v7版架构是最终权威: "策略大脑 (Fat Policy)" 继承自 BasePolicy，位于 G_policy。它在 __init__ 中装配所有 B_model 零件（VM/AM/Adapter/DM），并在内部精细化调度 self.adapter(obs) (仅提取1次特征) 和 self.dm (循环去噪)。
