# PADP v2 — 多环境采训推统一落地方案

> **v2 重构目的**(基于作者反馈,在 v1 基础上重写)
>
> 1. 模型编码器统一命名为 **VM / AM / LM / VLM / TM**,最后都用编码后的向量交互
> 2. 代码重组为 **5 大子文件夹**:`A_通用 / B_模型 / C_仿真 / D_真机 / E_采训推`
> 3. 训练和仿真都在 **4090**;采集和评估才走 **4090 + 4070** 双机
> 4. 频率统一基准:**控制 1 kHz** 固定,**采集/编码/去噪 = 整数倍** 基准
> 5. 数据 + 通信统一为 **LeRobot + "什么有什么发什么"**
> 6. 训练机 ↔ 部署机不强求联机,默认 server/client
> 7. 仿真和真机**每种机器人一个独立 env**

## 1. 总体目标与约束

### 1.1 项目目标

把 [PADP](../../PADP/PADP代码结构与功能.md) 现有「**单 task / 单仿真 / 单 env**」的代码结构,重构成两层架构:

| 模式 | 描述 |
|---|---|
| **仿真训练与推理** | 1 份模型 + 1 个或多个仿真环境**同时训练**,统一推理接口 |
| **真机部署** | 1 份模型 + 真机,**采集、训练(微调)、推理** 统一架构 |

**关键约束**

- **最多同时运行 2 个终端**(训练/仿真端 + 部署端 各 1)
- 仿真 = 1 台电脑(4090);部署 = 1 台或 2 台电脑(server/client 可拆)
- 仿真和真机**每种机器人一个独立 conda env**(`C_仿真` 内每个 sim 一 env,`D_真机` 内每种机器人一 env)
- 默认全部走 **server/client 分离** 结构

### 1.2 硬件约束

| 阶段 | 训练机 | 部署机 | 仿真机 | 采集机 | 评估机 |
|---|---|---|---|---|---|
| 训练 | **RTX 4090 24 GB** | — | — | — | — |
| 仿真 | 4090 | — | **4090**(同训练机) | — | — |
| 采集 | 4090(server) | **RTX 4070 12 GB** | — | **4090 + 4070** | — |
| 评估 | 4090(server) | 4070(client) | 4090(sim) | — | **4090 + 4070** |
| 真机持续部署 | — | 4070(server+client 同机) | — | 4070 | — |

**说明**
- 训练、仿真只跑 1 台 4090;采集、评估时双机(client + server),**2 终端**
- 真机持续部署时,server 和 client 都跑在 4070 上,可走 共享内存(同机)或 websocket(拆进程)

**Realsense 相机支持**:`405 / 415 / 435 / 455` 全系列,具体型号按手头硬件选(不同型号 depth / IMU / 视场角 不同,`D_真机/realsense/config/` 下挂各型号 profile)。

### 1.3 拆分动机

5 子文件夹 + 字母前缀,**目标就两件事**
- **部署灵活**:`A`/`B` 是跨 env 通用基础,可在不同 conda env / Docker 镜像中按需打包
- **切换零摩擦**:换模型(改 `B_模型`)/ 换仿真(改 `C_仿真`)/ 换机器人(改 `D_真机`),互不影响;`E_采训推` 把同一 env 的 采/训/推 配置集中,一键切换

### 1.4 本方案明确不做的事

- 不迁 JAX / Flax(单 GPU + diffusion + 定制 weight,JAX 红利不命中)
- 不上 Gemma / PaliGemma 量级 VLM 主干(4070 12 GB 装不下)
- 不做 TPU / 多机训练
- 不做 sim2real domain randomization 框架级支持
- 不打包模型在云端服务(本期都是同网段本地)

## 2. 设备连接与拓扑

### 2.1 训练 / 仿真阶段(单 4090)

```
            单 4090 工作站
            ┌──────────────────────────────┐
            │  终端 1                       │
            │  conda: padp-train           │
            │  bash 训/推                   │
            └──────────────────────────────┘
            数据源:
            ┌──────────────────────────────┐
            │  LeRobotDataset(NVMe / NAS)  │
            └──────────────────────────────┘
```

**只跑训练时 1 终端**;**跑训练 + 仿真评估时 2 终端**(训练端 + sim 端,见 §2.3)。

### 2.2 采集 / 评估阶段(4090 + 4070)

**2 终端分离**,对应 v1 "多进程" 思想,本方案统一为 "两台机各一终端":

```
  训练机 4090                          部署机 4070
  ┌────────────────────┐               ┌────────────────────┐
  │ 终端 1             │   websocket   │ 终端 2             │
  │ conda: padp-       │ ◄───────────► │ conda: padp-       │
  │   server           │  msgpack-     │   client           │
  │ encoder + denoiser │  numpy        │ sensor + control   │
  │  server            │               │ node               │
  └────────────────────┘               └─────────┬──────────┘
                                                │
                                                ▼
                                       ┌──────────────────┐
                                       │ Realsense ×N_cam │
                                       │ + Franka         │
                                       └──────────────────┘
```

### 2.3 部署形态选择矩阵

| 场景 | server | client | 通信 | 备注 |
|---|---|---|---|---|
| 训练时仅训不评估 | 4090(train 进程) | — | — | **不启动 sim/部署**(优化方向) |
| 训练时 + 仿真评估 | 4090(train 进程) | 4090(sim 进程) | 共享内存(同机)/ websocket(异机) | 2 终端 |
| 真机采集 | 4090(server) | 4070(client + sensor) | websocket / 共享内存 | 2 终端 |
| 真机评估 | 4090(server) | 4070(client + control) | websocket | 2 终端 |
| 真机持续部署(无 4090) | 4070(server) | 4070(client + control) | 共享内存 / websocket | 1 台机 2 进程 |

**默认 server/client 分离**,**不要求训练机与部署机联机**(checkpoint 走 `scp / rsync`)。

**备选 / 优化方向**
- **同机** → 共享内存(零拷贝,最快)
- **异机** → websocket + msgpack-numpy
- **只训练不评估** → 直接不起 sim 进程
- **评估并行** → 开多 sim 进程,每个连一个 server 实例

## 3. 数据格式与流

### 3.1 LeRobot 形式(数据 / 通信统一格式)

**所有数据源(sim / 真机)统一转 LeRobot 格式**:

| 来源 | 转换脚本(放 `E_采训推/采/to_lerobot/`) | 目标格式 |
|---|---|---|
| robomimic / mimicgen replay buffer | `robomimic_to_lerobot.py` | LeRobotDataset |
| pusht zarr | `pusht_to_lerobot.py` | LeRobotDataset |
| kitchen hdf5 | `kitchen_to_lerobot.py` | LeRobotDataset |
| 真实 Franka Realsense bag | `franka_bag_to_lerobot.py` | LeRobotDataset |

格式约定沿用 [GuidedVLA examples/*/convert_*_data_to_lerobot.py](../../GuidedVLA/PI0_PI05代码结构与功能.md):
- 视频帧:mp4 + 索引
- obs / state / action:parquet(Arrow 后端)
- 元数据:`fps` / `episode_index` / `frame_index` / `task`

字段级转换表(从 PADP zarr 到 LeRobot)见 [与现有代码的映射关系.md §9](与现有代码的映射关系.md)。

### 3.2 频率与延迟预算(以控制 1 kHz 为基准)

**核心思想**
- **控制下发频率恒为 1 kHz**,由插值器补齐策略输出的低频 action chunk
- **策略/去噪输出频率 = 基准 1**(denoise 一次出 H=16 步 chunk)
- **采集 / 编码器 / 去噪 = 基准 1 的整数倍**(倍数由硬件能力决定)

#### 当前 PADP 实测(待优化)

| 组件 | 频率 | 问题 |
|---|---|---|
| 采集 | 10 Hz | 真机 Realsense 默认频率,够用 |
| 系统评估 | 70 Hz | robomimic sim step |
| 编码器 + 去噪 串行 | 70 Hz | **串行是瓶颈**,vision 前向阻塞 denoise |
| 控制下发 | 1 kHz | 插值器 |

#### v2 目标(解耦 + 异步)

| 组件 | 频率(真机) | 频率(sim 评估) | 与基准 1 的倍数 | 备注 |
|---|---|---|---|---|
| 采集 | 30 Hz | 70 Hz | 3× / 7× | Realsense 上限 / sim step |
| 编码器 | 30 Hz | 70 Hz | 3× / 7× | 每帧新 obs 触发 |
| 去噪 | **10 Hz** | 10 Hz | **1× (基准 1)** | 每 3/7 帧 obs 触发一次,出 H=16 chunk |
| 控制下发 | **1 kHz** | 1 kHz | — | 插值器 |

**关键改进**:v1 把编码器 + 去噪绑成 70 Hz 串行 → v2 把编码器放低优先级 GPU stream,denoiser 独立 stream,**真并行**,denoise 频率不再被 vision 拖。

### 3.3 通信:"什么有什么发什么"

参考 [GuidedVLA src/openpi/serving/websocket_policy_server.py](../../GuidedVLA/PI0_PI05代码结构与功能.md) + [packages/openpi-client](../../GuidedVLA/PI0_PI05代码结构与功能.md),通信原则:

> **client 端有什么字段就发什么字段,server 端按收到的字段构造 obs,缺失字段用默认填充。**

这样:
- 加新传感器时不动协议
- 部署机硬件差异(单/双相机、有/无 depth)不影响 server
- 仿真与真机**共用一份 server 代码**(区别只在 client 的 `obs_action_adapter`)
- 405 / 415 / 435 / 455 不同 Realsense 型号(有些没 depth)混用无碍

具体 payload schema 见 [§8 接口契约](#8-接口契约)。

## 4. 模型架构

### 4.1 编码器族(模块清单)

`B_模型` 下的 5 类编码器,以及它们各自把什么输入变成什么向量:

| 编码器 | 输入 | 输出向量 | 候选实现 | 备注 |
|---|---|---|---|---|
| **VM**(Vision Model) | `rgb: [B, N_cam, 3, H, W]` | `img_tok: [B, N_cam·T_v, D_h]` | DINOv2-small / SigLIP-base / DINOv3 | 图像 patch token,空间信息 |
| **AM**(Action Model) | `a_t: [B, H, D_a]` | `[B, H, D_h]` | Conv1d + MLP | denoiser 输入层,与 denoiser 紧耦合 |
| **LM**(Language Model) | `list[str]`(prompt) | `txt_tok: [B, L, D_h]` + `txt_pool: [B, D_h]` | CLIP-text-base / T5-small | 任务语义 |
| **VLM**(Vision-Language Model) | `rgb + prompt` | `vl_tok: [B, L_vl, D_h]` | CLIP-ViT-B/32 / GuidedVLA models_pytorch | 视觉+语言联合表征;可替代 VM+LM |
| **TM**(Timestep Model) | `t: [B]` | `time_emb: [B, D_h]` | sinusoidal + 2-layer MLP | 扩散步嵌入 |

**所有编码器输出统一为 `D_h` 维向量**(默认 512),方便后续模块统一处理。

**VLM 的存在价值**
- 任务**强依赖视觉-语言对齐**(例:"夹住红色那个")时,VLM 联合表征比 VM + LM 拼起来更准
- VLM 可**替代** VM+LM,也可与 VM+LM **并存**(以 concat 形式喂给 denoiser)
- 本期推荐:VM + LM 简单组合(省显存);VLM 留给 ablation 阶段

### 4.2 模块间交互(在 B_模型 里选用)

denoiser 与各编码器向量的交互方式有 3 种,任选:

| 方式 | 适用 | 实现复杂度 | 算力开销 |
|---|---|---|---|
| **FiLM** | global 标量条件(state, time, text_pool) | 低 | 几乎 0 |
| **Cross-attention** | 空间/序列对齐(img_tok, txt_tok) | 中 | 中 |
| **Concat** | 同形状张量拼接(罕见) | 低 | 中 |

**默认搭配(本方案基线)**
- `state` + `time_emb` + `txt_pool` → **FiLM**(全 layer 影响)
- `img_tok` → **Cross-attention**(每个 down/mid/up block)
- `txt_tok` → **Cross-attention**(只在 mid block)
- `a_t` → **直接作为 UNet 输入**(AM 嵌入)
- `position weight` → **作用在 loss**(沿用 PADP `schedulers_padp.py`)

### 4.3 训练策略(消融实验维度)

每个编码器 3 选 1:**全冻结 / LoRA / 全量微调**。组合空间 ≈ 3⁵ = 243 种,实际 ablation 只跑关键组合:

| 组合 | 训练量 | 预期收益 | 适用 |
|---|---|---|---|
| 全冻结 | 0 | baseline | 第一版打通 |
| 全冻结 + LM LoRA | 轻 | 任务对齐好 | **推荐 v1** |
| 全冻结 + VM LoRA | 中 | 视觉对齐 | 数据异质时 |
| 全量微调 | 重 | 性能上限 | 4090 富余时 |

**LoRA rank = 16**(默认),具体放在 `B_模型/<encoder>/lora.py` 等子模块。

## 6. 加速思路

### 6.1 训练侧(4090)

按收益排序:

| # | 优化项 | 预期收益 | 工作量 |
|---|---|---|---|
| 1 | VM / LM / VLM 默认冻结 | 显存 −50%,训速 +30% | 极小 |
| 2 | bf16 mixed precision | 显存 −40%,训速 +60% | 小 |
| 3 | 冻结编码器特征离线缓存 | 训速 +2–3× | 中 |
| 4 | `torch.compile(denoiser)` | 训速 +30–50% | 小 |
| 5 | Flash Attention 2 for cross-attn | 显存 −30%,训速 +20% | 极小 |
| 6 | Gradient checkpoint mid block | 显存 −20% | 小 |
| 7 | 大 batch + grad accumulation | 收敛快 | 极小 |
| 8 | LoRA 灵活开关(消融用) | 表征精度 ↑ | 中 |

### 6.2 部署侧(4070)

```
4070 单次推理 latency 预算(目标):
┌──────────────────────────────────────────────────────────────┐
│  1 次完整推理 (cond 更新 + denoise + 输出 chunk)              │
│                                                              │
│  VM  ────────────  35ms  (INT8 DINOv2-small, 1 次/30ms)      │
│  LM  ─           0ms   (prompt cache)                        │
│  AM  ─           1ms                                        │
│  TM  ─           1ms                                        │
│  Denoise ────   25ms  (DDIM 4 步 × ~6ms, INT8 UNet)         │
│  Post   ─       3ms                                         │
│  Total       ~65ms → chunk 频率 ~15 Hz                       │
│                                                              │
│  1 kHz 控制由插值器 chunk → 1 kHz 完成                       │
└──────────────────────────────────────────────────────────────┘
```

v1 → v2 关键改进
- **编码器+去噪串行(70 Hz)** → **解耦两路 stream**,denoise 频率不再被 vision 拖
- **10 Hz 采集 70 Hz eval** → 训练时 30 Hz 真机 / 70 Hz sim,**denoise 频率独立选 10/15 Hz**
- 4070(12 GB)比 4060(8 GB)多 50% 显存,INT8 不再是必须,FP16 也行

### 6.3 量化与编译路径

| 路径 | 工作量 | 收益 | 何时用 |
|---|---|---|---|
| A. torch dynamic quantize | 极小 | −20% latency | 第一版打通 |
| B. ONNX Runtime INT8 | 中 | −40% latency | **推荐 v1** |
| C. TensorRT INT8 | 大 | −60% latency | 极限性能 |

**首版走 B 路径**,达标后再上 C。

### 6.4 部署性能基准

`E_采训推/推/benchmark.py` 固定测:
- 输入 shape `[1, 2, 3, 224, 224]` + `[1, 14]` state

- 输出:latency p50/p99 + 显存 + 4 步成功率

## 10. 风险与回退

| 风险 | 概率 | 影响 | 回退 |
|---|---|---|---|
| 4070 装不下 VM INT8 + UNet INT8 + 文本 | 低 | 高 | 退 FP16;或拆 2 卡 |
| DDIM 4 步成功率不够 | 中 | 中 | DPM-Solver++ 6 步;或 10 步 + 加 chunk 长度 |
| 多 sim 混训互相干扰,某 task 反而退化 | 高 | 中 | 每 task 独立 head |
| LeRobot mp4 IO 慢成瓶颈 | 低 | 中 | 退 zarr + 预解码 |
| 真机 vs sim 数据分布偏移 | 高 | 高 | 加真机数据继续训 |
| 同机 shm 冲突 / 跨网 ws 不稳定 | 中 | 中 | 改对端 IP + 重试 |
| 训练机 ↔ 部署机网段不通 | 低 | 低 | scp 离线同步 checkpoint |
| conda 多 env 维护成本超预期 | 低 | 中 | 合并部署 env 为单 env |
| Realsense 某型号在 win11 / 特定驱动下不稳 | 中 | 中 | 换型号 + 改 config/profile |
