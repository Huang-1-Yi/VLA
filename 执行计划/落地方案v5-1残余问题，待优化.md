### 🟡 P1-2:`padp_policy.py` 对 dim=3 obs 的 reshape 有潜在 bug

**位置**:`VLA/Gpolicy/PADP/padp_policy.py:204-207`

```python
this_obs = {
    k: (v[:, :n_obs_steps, ...].reshape(-1, *v.shape[2:]) if v.dim() >= 4
        else v[:, :n_obs_steps, ...].reshape(B, -1))   # dim=3 走这里
    for k, v in nobs.items()
}
```

**症状**:lowdim `(B, S, D)` 走 `reshape(B, -1)` → `(B, S*D)`,Adapter 看到 2D 设 T=1,

**真实触发条件**:`padp_for_test_golden.yaml:26` `n_obs_steps: 1` 改 `> 1` 即破。

**修法**(dim≥3 一致 flatten T):
```python
this_obs = {
    k: v[:, :n_obs_steps, ...].reshape(-1, *v.shape[2:])
    for k, v in nobs.items()
    if v.dim() >= 3
}
```

**为什么不是 P0**:当前 S=1,不触发;`padp_for_test_golden.yaml` 锁死 `n_obs_steps: 1`。

### 🟢 P2-1:`__getitem__` 多拼一次 "state" 键,Adapter 不消费

**位置**:`VLA/C_sim/robomimic/padp_for_test_dataset.py:373-376`

if self.lowdim_keys:

**位置**:`VLA/A_common/data/base_collator.py:26-28`

if all("window_info" in it for it in batch):

### 🟢 P2-3:`SingleFieldLinearNormalizer.create_from_stat` 的 /2 公式历史

**位置**:`VLA/A_common/types/normalizer.py:31-44`

```python
scale = (stat["max"] - stat["min"]) / (output_max - output_min)
offset = (stat["min"] + stat["max"]) / 2 - (output_min + output_max) / 2 * scale
```

**背景**:2026-06-14 修过 /2 bug(注释 line 39-40 说"旧公式有 /2 露馅")。当前公式数学正确
(已在 `test_action_rotation_conversion_consistent` 验证过 roundtrip 1e-6)。

**唯一可疑**:`range normalizer` 在输入常值维(`max == min`,input_range < 1e-7)时
`scale = 0 / 2 = 0`,`offset = (min + min) / 2 - 0 = min`。后续 `normalize(x) = (x - min) / (0 + 1e-8)`
会爆成 ±1e8 的 NaN-ish 大数。

**修法**(可选,边界 case):对常值维用 identity normalizer 而非 range:
```python
input_range = input_max - input_min
ignore_dim = input_range < range_eps
input_range[ignore_dim] = output_max - output_min
scale = (output_max - output_min) / input_range
offset = output_min - scale * input_min
offset[ignore_dim] = (output_max + output_min) / 2 - input_min[ignore_dim]
```

**为什么不是 P0**:当前 square_d0 数据集所有 lowdim 维都有非零 range,不会触发。

3. 动态 K 消融
4. 性能统计: client 端"平均在飞请求数",server 端"worker 队列长度"
