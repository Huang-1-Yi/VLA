## 一、记号约定(lerobot 风格 + VLA 扩展)

### 1.1 通用维度

| 符号 | 含义 | lerobot 对应 |
|---|---|---|
| `B` | batch 大小 | ✓ |
| `T_obs` | 观测时间窗(=`n_obs_steps`,默认 2) | ✓ `T_obs` 或 `n_obs_steps` |
| `T_pred` | 动作预测窗口(=`horizon`,默认 16) | ✓ `T_pred` 或 `horizon` |

### 1.2 自定义输入维度(VLA 扩展)

| 符号 | 含义 | 默认值 |
|---|---|---|
| `C, H, W` | 图像:channels / height / width | `C=3, H=84, W=84`(PADP 默认)|
| `N_pc, C_pc` | 点云:点数 / 每点通道(3=xyz, 6=xyz+rgb)| `N_pc=1024, C_pc=3 or 6` |
| `S` | 阶段标签(int 或 one-hot 长度)| 阶段 1 不启用(SM 占位)|
| `T_pc` | 点云时间窗(若有时序点云)| 阶段 3 启用 |

### 1.3 特征维度

| 符号 | 含义 | 备注 |
|---|---|---|
| `D_s` | 状态维度(joint pos + vel + gripper 等)| 14(robomimic square 默认 3+4+2+...;由 shape_meta 决定)|
| `D_a` | 动作维度 | 7(robomimic square 默认 7DOF)|
| `D_vm` | 视觉编码器**单相机**输出维度 | 各 VM 默认 64,RobomimicObsEncoder 默认 512 |
| `D_am` | 状态/动作编码器输出维度 | 默认由 cfg 决定 |
| `D_tm` | 时间步编码器输出维度 | 默认 512 |
| `D_sm` | 阶段编码器输出维度(占位)| 阶段 1 不启用,占位 |
| `D_proj` | Adapter 投影维度(== DM 的 `global_cond_dim`)| 默认 512 |
| `D_g` | DM 全局条件维度(== `D_proj`)| 512 |
| `D_l` | DM 局部条件维度(可选)| 默认 0(不用 local_cond)|

## 二、6 类组件逐个清单

### 2.1 VM —— Vision Model(视觉编码器)

**抽象契约**(`B_model/encoders/interface_vm.py`):
- 输入:单图 / 单 batch(多相机 + 多时间步由 Adapter 沿 batch 维 cat)
- 输出:`(B, D_vm)`,即**单相机 + 单时间步**特征
- `output_shape()` 返回 `(D_vm,)`,Policy 在 `__init__` 时调它决定 Adapter fusion 维度

#### 2.1.1 各实现的 `D_vm` 默认值

|---|---|---|---|---|
| `RobomimicObsEncoder` | `VM/robomimic_obs_encoder.py` | `(B, 3, 84, 84)` | `(B, 512)` | **512** |
| `TimmImageObsEncoder` | `VM/timm_image_obs_encoder.py` | `(B, 3, H, W)` | `(B, 64)` | **64** |
| `CLIPImageObsEncoder` | `VM/clip_image_obs_encoder.py` | `(B, 3, 224, 224)`(CLIP 强制 224)| `(B, 512)` | **512** |
| `TorchvisionResNetObsEncoder` | `VM/torchvision_resnet_obs_encoder.py` | `(B, 3, 76, 76)` | `(B, 64)` | **64** |
| `R3MObsEncoder` | `VM/r3m_obs_encoder.py` | `(B, 3, 76, 76)` | `(B, 64)`(r3m 未装时 fallback 到 torchvision)| **64** |

### 2.5 Adapter —— 特征融合器(VM/AM/TM/SM 集成点)

**抽象契约**(`B_model/adapters/base_adapter.py`):
- 输入:`obs` dict(含 N 个 rgb key + 多个 lowdim key,**未来**:stage key)
- 输出:global_cond `(B, T_obs, D_proj)` —— 保留时间窗,供 Policy 在 `__init__` 时按需 reshape 给 DM
- `output_shape()` 返回 `(D_proj,)`(报告**单时间步**维)

#### 2.5.1 当前实现:`PADPAdapter`

**`__init__` 签名**:
```python
def __init__(self, shape_meta: dict, vm_encoder: nn.Module,
             am_encoder: nn.Module = None, proj_dim: int = 512)
```

**forward 输入**:`obs` dict,典型 shape_meta(参考 PADP `square`):
```yaml
obs:
  agentview_image:           {shape: [3, 84, 84], type: rgb}
  robot0_eye_in_hand_image:  {shape: [3, 84, 84], type: rgb}
  robot0_eef_pos:            {shape: [3]}        # lowdim
  robot0_eef_quat:           {shape: [4]}        # lowdim
  robot0_gripper_qpos:       {shape: [2]}        # lowdim
```

**forward 各 key 期望 shape**:
| key 类型 | 期望 shape | 备注 |
|---|---|---|
| rgb key | `(B, T_obs, 3, 84, 84)` 或 `(B, 3, 84, 84)`(Adapter 自动 reshape)| 多相机沿 batch 维 cat |
| lowdim key | `(B, T_obs, D_s)` 或 `(B, D_s)`(Adapter 自动 unsqueeze)| AM 投影后 cat |
| **(未来) stage key** | `(B,)` 或 `(B, D_sm)` | 阶段 2/3 启用 |

**forward 各步输出 shape**(PADPAdapter 内部):
| 步骤 | 形状 |
|---|---|
| 1. rgb cat 后 | `(B*T_obs*N_cam, 3, 84, 84)` |
| 2. VM 输出 | `(B*T_obs*N_cam, D_vm)` |
| 3. reshape + flatten cameras | `(B, T_obs, N_cam * D_vm)` |
| 4. AM 输出(若有) | `(B, T_obs, D_am)` |
| 5. cat rgb + lowdim | `(B, T_obs, N_cam*D_vm + D_am or D_lowdim)` |
| 6. `fusion` Linear 投影 | **`(B, T_obs, D_proj)`** |
| **`output_shape()`** | **`(D_proj,)`**(单步维)|

**默认 `proj_dim`(`D_proj`)**:**512**

#### 2.5.2 当前实现:`DPAdapter`

`DPAdapter` 结构与 `PADPAdapter` 完全相同,只是不做位置加权(loss 由 DP compute_loss 处理)。

### 2.6 DM —— Diffusion Network(动作去噪网络)

**抽象契约**(`B_model/networks/interface_dm.py`):
- 输入 `sample`:`(B, T_pred, D_a)` 加噪动作序列
- 输入 `**cond`:`global_cond: (B, D_g)` + `local_cond: (B, T_pred, D_l)` or None
- 输出:`(B, T_pred, D_a)` —— 与 sample 同 shape
- `output_shape()` 返回 `(D_a,)`

#### 2.6.1 当前实现:`Unet1DPadp`

**`__init__` 签名**:
```python
def __init__(self, input_dim: int, local_cond_dim=None, global_cond_dim=None,
             down_dims=(256, 512, 1024), kernel_size=5, n_groups=8,
             cond_predict_scale=False)
```

**forward 签名**:
```python
def forward(self, sample, local_cond=None, global_cond=None, **kwargs)
```

**forward 输入/输出**:
| 参数 | 形状 | 默认值 / 来源 |
|---|---|---|
| `sample` | `(B, T_pred, D_a)` | `D_a=7`(square 默认),`T_pred=16`(=horizon) |
| `local_cond` | `(B, T_pred, D_l)` or None | 阶段 1 **不用**,传 None |
| `global_cond` | **`(B, D_g)` 单步维** | `D_g = D_proj`(**由 Adapter 输出 reshape 来**)|
| **返回** | `(B, T_pred, D_a)` | 与 sample 同 shape |
| `output_shape()` | `(D_a,)` | 单步维 |

**内部 down/up 通道**:`down_dims = (256, 512, 1024)`(默认,3 层下采样)

**`global_cond` 关键约束**:
- 接口要求 `(B, D_g)` —— **单 batch 维,不含 `T_obs`**
- Policy 内部需把 Adapter 输出 `(B, T_obs, D_proj)` reshape 到 `(B, D_proj)`(沿 T 维 flatten)再传给 DM
- 阶段 1 PADP 的 `padp_policy.py:forward` 是直接传 `global_cond=(B, T_obs, D_proj)`,**这是个潜在 bug**——会在 DM 内部 `cond_encoder(Linear(D_g, D_cond))` 时形状不匹配。修复待阶段 1 联调时再处理。

## 三、6 类组件的形状流转图(完整链路)

```
# E_cti 喂给 Policy 的 obs dict(参考 PADP square)
obs = {
    "agentview_image":          Tensor[B, T_obs, 3, 84, 84],
    "robot0_eye_in_hand_image": Tensor[B, T_obs, 3, 84, 84],
    "robot0_eef_pos":           Tensor[B, T_obs, 3],
    "robot0_eef_quat":          Tensor[B, T_obs, 4],
    "robot0_gripper_qpos":      Tensor[B, T_obs, 2],
    # 阶段 2/3:
    # "stage_label":             Tensor[B],                # SM 输入
    # "point_cloud":             Tensor[B, T_obs, 1024, 3],  # DP3ObsEncoder 输入
}
# 加噪动作
a_t = Tensor[B, T_pred, 7]    # T_pred=horizon=16, D_a=7
t  = Tensor[B]                  # 扩散时间步

# === 形状流转链 ===
# 步骤 1: Adapter 吃 obs dict
adapter_out = adapter(obs)                                    # (B, T_obs, 512)   — D_proj=512
#   内部:
#     - VM rgb 路径: (B, T_obs, 3, 84, 84) → reshape (B*T_obs, 3, 84, 84)
#                                         → cat 2 cameras → (B*T_obs*2, 3, 84, 84)
#                                         → VM → (B*T_obs*2, 64)
#                                         → reshape (B, T_obs, 2*64)
#     - AM 路径:    (B, T_obs, 9) → Linear → (B, T_obs, 64)
#     - fusion:     cat([rgb_feat, am_feat], dim=-1) → Linear → (B, T_obs, 512)

# 步骤 2: Policy.forward 把 global_cond flatten 给 DM
# 注:这一步当前是潜在 bug,见 §2.6.1 末尾
global_cond = adapter_out.flatten(0, 1)  # (B*T_obs, 512)  ← 实际是 (B, T_obs, 512)
                                             # DM 期望 (B, 512),需 reshape
# 正确做法:
global_cond = adapter_out.mean(dim=1)     # (B, 512)  ← 沿 T 维 mean pool

# 步骤 3: TM 编码时间步
tm_emb = tm(t)                              # (B, 512)      — D_tm=512

# 步骤 4: DM 单步去噪
pred_noise = dm(a_t, global_cond=global_cond)  # (B, T_pred, 7)
# 内部:把 global_cond 经 Linear 注入到每层 FiLM,逐层下采样再上采样
# 注: 实际把 (B, 512) reshape 成 (B, 512, 1) 喂 cond_encoder

# 步骤 5: 损失
loss = ((pred_noise - noise) ** 2 * w[None, :, None]).mean()  # scalar
```

## 四、跨组件接口不变量(给 Policy / Adapter 作者参考)

### 4.1 形状不变量

| 不变量 | 含义 |
|---|---|
| `B` 在整条链路中**保持不变** | VM / AM / TM / Adapter / DM 都不缩减 batch 维 |
| `T_obs` 在 VM / AM / Adapter **保留**,在 DM **变为 `T_pred`** | VM/AM 看历史,DM 看未来动作 horizon |
| `T_pred` (= horizon) 与 `T_obs`(=n_obs_steps) **独立** | 不要求相等(可以 16 vs 2)|
| `D_vm` × `N_cam` 是**单时间步** RGB 特征总量 | Adapter 把它 reshape 进 (B, T_obs, N_cam*D_vm) |
| `D_proj` == DM 的 `global_cond_dim` | Adapter 的输出 = DM 的输入 cond;**两者必须配对** |
| `D_a` == ActionOutput.actions.shape[-1] | DM 输出 = Adapter 反归一化的输入 = ActionOutput 动作 |

### 4.2 关键不配对会报错的边界

| 配对 | 不匹配错误 |
|---|---|
| Adapter `D_proj` vs DM `global_cond_dim` | `RuntimeError: mat1 dim mismatch`(Linear 投影时) |
| VM `D_vm` vs Adapter fusion 输入 dim | 同上 |
| DM 输出 `D_a` vs ActionOutput.actions dim | 后续 `unnormalize` 时索引错误 |
| Adapter 输入 rgb shape 5D vs VM 输入 4D | Adapter 内部 reshape 自动处理,无需手动 |

### 7.9 训练时真正应该用的配置(从 §五 + 实测综合)

如果要"端到端训练"而**不是测试**,把测试里的 `proj_dim=64` / `dim=64` 改回 §五默认:

```python
# test_encoders_output.py 第 152-162 行附近(测试用小值,实际训练需改回):
TimmImageObsEncoder(model_name="resnet18", pretrained=False, proj_dim=64)  # → 改 proj_dim=64 → 默认是 cfg 决定
# RobomimicObsEncoder 默认 proj_dim=512(已在 §五 列)
# SinusoidalTimestepEncoder 默认 dim=512(已在 §五 列)
```

> **提示**:改回默认值后,VM 输出维会变成 512(而非 64),Adapter 的 `fusion_in_dim = n_cameras * D_vm + D_am` 也会跟着变。务必在 cfg 里 `adapter.proj_dim` 与 `dm.global_cond_dim` **配对设置**——这是 §四"关键不配对会报错"列的第一条。
